# Лабораторна робота №2

Клієнтський застосунок для управління бібліотекою, виконаний на TypeScript. Інтерфейс повністю генерується з коду через DOM API, а `index.html` містить лише контейнер `#app`.

## Запуск

```bash
npm install
npm run start
```

Dev-сервер webpack запускається на `http://localhost:9000`.

## Реалізовано

- моделі `Book` та `User` з інтерфейсами і методами доступу;
- generic-клас `Library<T>` для додавання, видалення та пошуку сутностей;
- клас `Storage` для роботи з LocalStorage;
- namespace `Validation` для перевірки обов'язкових полів, цифрового ID, email та року видання;
- додавання, видалення, пошук, пагінація книг і користувачів;
- позичання та повернення книг з обмеженням до 3 книг на одного користувача;
- модальні сповіщення без використання `alert`;
- стилізація через Bootstrap, підключений як npm-залежність через webpack;
- Mocha/Chai тести для `Library` та `Validation`;
- ESLint, Prettier і Husky pre-commit hook.

## Структура

`models` містить чисті класи та інтерфейси даних. `services` відповідає за бізнес-логіку і збереження стану. `utils` містить допоміжні функції та namespace валідації. `ui` є єдиним шаром, який працює з DOM.

## Висновок щодо webpack і Vite

Webpack дає детальний контроль над entry, output, loaders, devServer та обробкою стилів, але потребує більше конфігурації. Для цього проєкту потрібно явно налаштувати `ts-loader`, правила для SCSS/CSS і dev-server.

Vite для невеликих SPA зазвичай стартує швидше, має простіший конфіг і швидший HMR, тому суб'єктивно зручніший для подібної лабораторної. Webpack краще показує, як саме працює збірка і які кроки потрібні для TypeScript та стилів, але для повсякденної розробки такого застосунку Vite простіший.

## Контрольні питання

1. TypeScript додає статичну типізацію, автодоповнення, раннє виявлення помилок і кращу підтримку великих кодових баз.
2. Клас створює об'єкти і може містити реалізацію методів, а інтерфейс описує контракт форми даних. Інтерфейс доречний для опису `IBook` або `IUser`.
3. Generics дозволяють `Library<T>` працювати з різними типами сутностей без втрати типізації. Без generic довелось би використовувати слабші типи.
4. ES-модулі розділяють код між файлами через `import/export`, а namespace групує пов'язані функції всередині модуля. У цій роботі namespace використано для `Validation`.
5. `models` описує дані, `services` містить бізнес-логіку, `utils` містить допоміжну логіку, `ui` рендерить DOM.
6. `Storage` серіалізує масиви книг і користувачів у LocalStorage та відновлює їх після перезавантаження. LocalStorage має обмежений обсяг і зберігає лише рядки.
7. Позичання записує ID користувача в книгу та ID книги користувачу. Повернення очищає ці зв'язки.
8. Валідація перевіряє порожні поля, цифровий ID та рік через регулярний вираз для років від 1500 до поточного року.
9. Один користувач може мати максимум 3 книги. При перевищенні застосунок показує модальне повідомлення.
10. Розмітка в `index.html` заборонена, щоб закріпити програмне створення DOM. Уся структура створюється у `renderApp`.
11. `webpack.config.js` задає entry, output, `ts-loader`, loaders для стилів і `devServer`.
12. ESLint шукає проблеми якості коду, Prettier уніфікує форматування.
13. Тести Mocha перевіряють додавання, видалення, пошук у `Library`, а також обов'язковість полів, ID і рік у `Validation`.
14. Husky pre-commit запускає лінтер і тести перед комітом, щоб не допустити зламаний код у репозиторій.
15. Webpack гнучкіший і детальніший, Vite швидше стартує та простіше налаштовується для малих SPA.
